# Orchestration & Apache Airflow

Orchestration involves managing dependencies between data tasks, scheduling them, and monitoring their execution. Apache Airflow is the industry standard "Workflow as Code" platform.

## Airflow Architecture
*   **Scheduler:** Monitors all tasks and DAGs, triggers task instances once their dependencies are complete.
*   **Executor:** Defines how tasks are executed (Sequential, Local, Celery, Kubernetes).
*   **Webserver:** UI to inspect, trigger, and debug DAGs.
*   **Metadata Database:** Stores state of tasks, DAGs, variables, connections (PostgreSQL/MySQL).

### Key Concepts
*   **DAG (Directed Acyclic Graph):** A collection of all the tasks you want to run, organized in a way that reflects their relationships and dependencies.
*   **Operator:** A template for a specific task (e.g., `PythonOperator`, `BashOperator`, `BigQueryOperator`).
*   **Task:** An instantiated Operator.
*   **XCom (Cross-Communication):** Mechanism for tasks to exchange small amounts of data/metadata.

### dbt (data build tool)
dbt is strictly for the **Transformation** (T) in ELT. It allows you to write SQL `SELECT` statements, and it handles the DDL (creating tables/views) for you. Airflow often orchestrates dbt jobs using the `BashOperator` to run `dbt run`.

## Develop an End-to-End ML Pipeline

**Goal:** Data Prep -> Model Training -> Model Evaluation -> Deployment.

**File:** `dags/ml_pipeline.py`

```python
from airflow import DAG
from airflow.operators.python import PythonOperator
from airflow.providers.google.cloud.operators.bigquery import BigQueryExecuteQueryOperator
from datetime import datetime, timedelta

def train_model(**context):
    import pandas as pd
    from sklearn.linear_model import LogisticRegression
    import pickle
    
    # In reality, read from GCS/S3
    data_path = context['ti'].xcom_pull(task_ids='data_preparation')
    print(f"Reading data from {data_path}")
    
    # Mock training
    model = LogisticRegression()
    # model.fit(...)
    
    model_path = '/tmp/model.pkl'
    with open(model_path, 'wb') as f:
        pickle.dump(model, f)
        
    return model_path

def evaluate_model(**context):
    model_path = context['ti'].xcom_pull(task_ids='train_model')
    print(f"Evaluating model at {model_path}")
    accuracy = 0.95
    if accuracy < 0.9:
        raise ValueError("Model accuracy too low!")
    return accuracy

default_args = {
    'owner': 'airflow',
    'retries': 1,
    'retry_delay': timedelta(minutes=5),
}

with DAG(
    'end_to_end_ml_pipeline',
    default_args=default_args,
    description='A simple ML pipeline',
    schedule_interval='@daily',
    start_date=datetime(2023, 10, 1),
    catchup=False,
) as dag:

    # Step 1: Data Preparation (SQL in BigQuery)
    data_prep = BigQueryExecuteQueryOperator(
        task_id='data_preparation',
        sql='''
            create or replace table `my_project.dataset.training_data` as
            select * from `my_project.dataset.raw_logs`
            where date = DATE('{{ ds }}')
        ''',
        use_legacy_sql=False,
    )

    # Step 2: Training (Python)
    training = PythonOperator(
        task_id='train_model',
        python_callable=train_model,
    )

    # Step 3: Evaluation
    evaluation = PythonOperator(
        task_id='evaluate_model',
        python_callable=evaluate_model,
    )
    
    # Step 4: Notification / Deployment (Mock)
    deploy = PythonOperator(
        task_id='deploy_model',
        python_callable=lambda: print("Model Deployed!"),
    )

    # Define Dependencies
    data_prep >> training >> evaluation >> deploy
```
