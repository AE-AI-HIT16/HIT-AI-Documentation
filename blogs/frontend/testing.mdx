# Frontend Testing

Testing frontend applications ensures reliability and prevents regressions.

## Testing Types

### 1. Unit Testing

Test individual components in isolation:

```jsx
import { render, screen } from '@testing-library/react';
import Button from './Button';

test('renders button with text', () => {
  render(<Button>Click me</Button>);
  const button = screen.getByText('Click me');
  expect(button).toBeInTheDocument();
});

test('calls onClick when clicked', () => {
  const handleClick = jest.fn();
  render(<Button onClick={handleClick}>Click me</Button>);
  
  fireEvent.click(screen.getByText('Click me'));
  expect(handleClick).toHaveBeenCalledTimes(1);
});
```

### 2. Integration Testing

Test component interactions:

```jsx
import { render, screen, fireEvent } from '@testing-library/react';
import LoginForm from './LoginForm';

test('submits form with valid data', async () => {
  const onSubmit = jest.fn();
  render(<LoginForm onSubmit={onSubmit} />);
  
  fireEvent.change(screen.getByLabelText('Email'), {
    target: { value: 'user@example.com' }
  });
  fireEvent.change(screen.getByLabelText('Password'), {
    target: { value: 'password123' }
  });
  fireEvent.click(screen.getByText('Submit'));
  
  await waitFor(() => {
    expect(onSubmit).toHaveBeenCalledWith({
      email: 'user@example.com',
      password: 'password123'
    });
  });
});
```

### 3. E2E Testing

Test complete user flows:

```javascript
// Playwright example
import { test, expect } from '@playwright/test';

test('user can login and view dashboard', async ({ page }) => {
  await page.goto('https://example.com/login');
  
  await page.fill('#email', 'user@example.com');
  await page.fill('#password', 'password123');
  await page.click('button[type="submit"]');
  
  await expect(page).toHaveURL('https://example.com/dashboard');
  await expect(page.locator('h1')).toContainText('Dashboard');
});
```

## Testing Best Practices

### 1. Test User Behavior

```jsx
// ❌ Bad: Testing implementation
expect(component.state.count).toBe(1);

// ✅ Good: Testing user behavior
expect(screen.getByText('Count: 1')).toBeInTheDocument();
```

### 2. Use Accessible Queries

```jsx
// ❌ Bad: Using class names
const button = container.querySelector('.btn-primary');

// ✅ Good: Using accessible queries
const button = screen.getByRole('button', { name: 'Submit' });
```

### 3. Mock External Dependencies

```jsx
// Mock API calls
jest.mock('./api', () => ({
  fetchUser: jest.fn(() => Promise.resolve({ id: 1, name: 'John' }))
}));
```

### 4. Test Error States

```jsx
test('displays error message on API failure', async () => {
  jest.spyOn(api, 'fetchData').mockRejectedValue(new Error('API Error'));
  
  render(<DataComponent />);
  
  await waitFor(() => {
    expect(screen.getByText('Error loading data')).toBeInTheDocument();
  });
});
```

## Test Coverage

### Coverage Goals

- **Statements**: > 80%
- **Branches**: > 75%
- **Functions**: > 80%
- **Lines**: > 80%

### Generate Coverage Report

```bash
# Jest
npm test -- --coverage

# Vitest
npm test -- --coverage
```

## Continuous Testing

### GitHub Actions

```yaml
name: Tests

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: '18'
      - run: npm install
      - run: npm test
      - run: npm run test:e2e
```

## Best Practices

1. **Write Tests First**: TDD approach
2. **Test User Behavior**: Not implementation details
3. **Keep Tests Simple**: One assertion per test
4. **Use Descriptive Names**: Clear test descriptions
5. **Mock External Services**: Isolate components
6. **Maintain Test Coverage**: Aim for 80%+
7. **Run Tests Frequently**: Catch issues early
